## Problem description

Both slugs appear twice in `dreamSymbolEntries`:

1. **batch-o** — generated by `rich(slug, title)` string template (same skeleton for ~100 symbols)
2. **batch-as** — hand-authored, symbol-specific copy

Production lookup:

```ts
// data/dream-symbols.ts
export function getDreamSymbolBySlug(slug: string) {
  return dreamSymbols.find((symbol) => symbol.slug === slug);
}
```

`Array.find` returns the **first** match. Because `batch-o` is concatenated before `batch-as` in `dream-symbol-entries.ts`, the **generic O record is live**. The AS record is unreachable via page/metadata/related resolution for that slug.

`generateStaticParams` maps every entry → duplicate `{ slug }` params for the same URL key.

## Canonical decision (justified)

| Slug | Canonical record | Discard |
|------|------------------|---------|
| `okula_gec_kalmak` | **batch-as** hand-authored | batch-o `symbols` tuple |
| `sinava_gec_kalmak` | **batch-as** hand-authored | batch-o `symbols` tuple |

**Why not keep O:** It is live today only due to array order, not quality. Keeping O would continue serving non-specific content and would discard AS work.

**Why not merge field-by-field:** O fields add no unique factual/cultural value; they are template strings. Merging would reintroduce boilerplate into AS.

**Why not rename O:** Would create a third URL for the same title and worsen SEO confusion.
